# 🇹🇭 เริ่มต้นใช้งาน

API นี้คือชุดเดียวกับที่ทุกหน้าของ OneService เรียกใช้ (สำหรับทีมพัฒนาภายใน) · ทุก path อยู่ใต้ `/api` · ไม่มี API key — เรียกในนามคนที่ login อยู่ ภายใต้สิทธิ์ของบทบาทนั้น

## ยืนยันตัวตน (session)

- เข้าสู่ระบบผ่าน SSO กลาง (`/api/sso/login` → `/api/sso/callback`) ได้ cookie `os_session` (httpOnly — เบราว์เซอร์ส่งให้เอง)
- ไม่ได้ใช้ 30 นาทีหมดอายุ (ต่อด้วย `GET /api/sso/refresh`) · นานสุด 12 ชั่วโมงนับจาก login
- ออกจากระบบ = ทุกเครื่องของคนนั้นหลุดพร้อมกัน (session_version)
- สิทธิ์มาจากบทบาท (app_config): ดู / เพิ่ม / แก้ไข / ลบ ต่อโมดูล + สิทธิ์พิเศษ (เช่น SO Approve, Export, Product Cost) · ยังไม่อนุมัติหรือไม่มีสิทธิ์ = `403`
- ไม่ต้อง login: `/api/health`, `/api/sso/*`, `/api/track/*` (หน้าติดตามของลูกค้า) และโลโก้ใน `/api/files`

## Try it ในหน้านี้

ยิงไปที่เว็บที่เปิดหน้านี้อยู่ ด้วย session ของคุณเอง · endpoint ที่มี body ใส่ตัวอย่างไว้ให้แล้ว แก้แล้วกด **Send**

⚠️ บน production คือ **ข้อมูลจริง** — สร้าง/แก้/ลบ มีผลจริง

## เขียนข้อมูล: JSON เท่านั้น (CSRF)

- body ต้องเป็น JSON และส่ง `Content-Type: application/json` · อย่างอื่นได้ `415` · ใหญ่เกิน 1 MB ได้ `413`
- การเขียนที่มี cookie จากเว็บอื่น (cross-site) ถูกปฏิเสธที่ proxy (`403`)
- อัปโหลดไฟล์ (`/api/upload`, `/api/attachments`) เป็น `multipart/form-data` ไม่เกิน 10 MB

## ข้อผิดพลาด

```json
{ "error": "กรอกข้อมูลไม่ครบ 2 ช่อง", "details": { "fields": { "phone": "ต้องระบุเบอร์โทรศัพท์" } } }
```

- `error` = ข้อความภาษาไทยไว้แสดงผู้ใช้ (ถ้อยคำไม่ใช่สัญญา อย่า parse)
- `400` กฎฟอร์มไม่ผ่าน: `details.fields` = { ช่อง: ข้อความ } · กฎชุดเดียวกับหน้าเว็บ (`src/lib/validation`)
- `401` ไม่มี session / หมดอายุ · `403` ไม่มีสิทธิ์ · `404` ไม่พบ
- `409` ชนกัน: `details.stale` (ดู row_version) · ข้อมูลซ้ำ · สถานะไม่อนุญาตแล้ว
- `429` เรียกถี่เกิน: `details.retryAfter` วินาที
- `500` ไม่คาดคิด: มี `ref` ไว้แจ้งทีม (รายละเอียดอยู่ใน log ฝั่ง server) · `503` DB ไม่ตอบ / query นานเกิน
- `/api/track/*` ตอบอีกแบบ: `{ "ok": false, "error": "…", "reason": "link" | "session" | "captcha" }`

## Idempotency-Key (กันกดซ้ำ)

POST ที่สร้างเอกสาร (งาน, ลูกค้า, ใบเสนอราคา, ใบสั่งขาย, รับเข้า/จ่ายออก) รับ header `Idempotency-Key`:

- หนึ่ง key ต่อการกดบันทึกหนึ่งครั้ง (`src/lib/api.ts` postJson ส่งให้เอง)
- ส่ง key เดิมซ้ำ = ได้คำตอบเดิม (header `Idempotent-Replayed: true`) ไม่เกิดเอกสารใบที่สอง
- ซ้ำระหว่างที่ครั้งแรกยังทำงานอยู่ = `409` · key เดิมกับ route อื่น = `422` · ครั้งแรกล้มเหลว = ใช้ key เดิมส่งใหม่ได้

## row_version (แก้พร้อมกัน → 409)

- รายละเอียดเอกสาร (งาน, ลูกค้า, ใบเสนอราคา, ใบสั่งขาย, อะไหล่) มี `version`
- ตอนบันทึกการแก้ไข ส่ง `version` ที่โหลดมากลับไปด้วย · ถ้ามีคนบันทึกไปก่อน = `409` + `details.stale: true` → โหลดใหม่แล้วแก้อีกครั้ง
- ไม่ส่ง `version` = เขียนทับแบบเดิม (last write wins)

## รายการและแบ่งหน้า

- `GET /api/data/{resource}` = ฝั่งอ่านของทุกหน้า · ปกติตอบเป็น array
- `paged=1` = ตอบทีละหน้า `{ rows, total, page, pageSize }` · `page` เริ่ม 1 · `pageSize` 1–500 (ค่าเริ่มต้น 25) · `sort` + `dir` (`asc` / `desc`) · `q` ค้นหา
- `deleted`: `exclude` (ค่าเริ่มต้น: ทุกอย่างยกเว้นที่ลบ) / `active` / `only` / `all` — ลบ = soft delete (`record_status`)
- วันที่เป็น `YYYY-MM-DD` เวลาไทย · `GET /api/export/{resource}` ตัวกรองเดียวกัน ได้ไฟล์ Excel
